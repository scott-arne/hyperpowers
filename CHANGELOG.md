## 6.11.1 (2026-08-26)

A blocking finding raised in the gate's last permitted round had a silent default, and the ledger append that follows it read as free.

- **The backstop's tail finding now forces a stated choice.** A blocking finding first raised IN the backstop round has no round left to confirm its fix — the round that found it is the last one. §5 already conceded the consequence ("fixes applied in the backstop round ship without a confirming Codex pass") but left *fixing it* as the unstated default, so the decline option §5 grants two steps earlier was invisible exactly where it matters most. The stop-condition now names three dispositions with each one's price: **decline** with recorded reasoning (ships no unverified change and buys no follow-on gate — usually right when the fix is not trivial), **fix and open the follow-on review now** while the context is live, or **fix and defer**, only after telling your human partner plainly that a blocking-severity fix rides unreviewed until that review happens.
- **The `backstop-fix` ledger append is priced, not bookkeeping.** A pending event does not discharge a gate — `gate-sweep` gives each one a fresh `GATE_DIR` and runs the full §5 loop at the code-gate ceiling. So both fix paths cost the same extra gate and differ only in when it is paid, and the text now says so. A downstream project hit this twice in one branch and paid two unbudgeted gates for it; the price was recoverable from §7, but nothing on the fix loop's own route pointed at it. The consequence is stated without naming the section: no route contains both `gate-fix-loop` and `gate-sweep`, so a pointer there would be the same dangling reference the approach gate just had removed.
- **"Budget a round for the fix" was the reported remedy and does not work.** For any finite ceiling the last round has no successor, and the round-aware preamble explicitly permits genuinely new blocking findings on re-review — so reserving a round turns a finding budget of 3 into 2 with an identical ungated tail. The gap is a property of terminating, not of the ceiling's size. What the tail needs is a decision procedure, not more budget.
- **New eval scenario** `codex-gate-backstop-finding-forces-choice` (in the separate evals clone): a stub Codex returns a different blocking finding every round, so the loop cannot converge and exits by backstop with a live finding. Deterministic checks pin the skill invocation, the companion call, and one `gate-round` invocation carrying the code-gate `--ceiling 3`; whether the disposition was named — and its price stated — is graded from the story's acceptance criteria. The ungated-ledger append is deliberately not asserted: declining is a legal disposition and writes no entry, so requiring it would fail the best answer.
- **Release gating.** Offline: every suite passes, with `test-gate-contract.sh` at 124 assertions (five new needles, one per branch of the choice plus the priced append), `test-gate-split-lossless.sh` at 26 PASS / 0 SKIP over 10 declared post-split edits, topology 47, placement 28, assemble 8, `test-sdd-contract.sh` at 95, shell lint clean. The rewritten line is declared in `gate-post-split-edits.tsv`, so the losslessness proof still reconstructs the pre-split original byte-for-byte. The proof's overlap guard was narrowed to `rewrite` rows — a `verbatim` reference row substitutes nothing and so cannot race a content edit of the same line — and the narrowing was mutation-tested against a real rewrite line. Evals harness: `bun run lint`, `bun run typecheck`, and `bun run quorum check` clean; `bun test` passes apart from four load-dependent 5000ms timeouts on temp-dir fixtures that all pass at a 30s timeout. Live: not re-run for this release.

## 6.11.0 (2026-08-26)

Subagent-driven development's progress record and evidence discipline, a new controller-fix carve-out, and two test suites that could report PASS without observing anything.

- **The ledger — not conversation memory — is SDD's progress record.** The implementer's agent identity is written into the ledger when the dispatch returns, so a controller resuming after compaction can still resolve fix-loop rounds 1-3 to the agent that did the work instead of dispatching a stranger. Todos mirror the ledger where they are surfaced rather than competing with it, and resume now classifies an in-flight dispatch instead of reading a task with no completion line as never started.
- **A covering command that cannot fail is not evidence.** Every implementer and fix dispatch names either a real covering command or an explicit `no covering command: <rationale>` line plus the controller's substitute verification; a dispatch naming neither is malformed. The controller re-runs the named command itself before acting on any completed-status report — the worked example now shows that re-run before both the review and the re-review.
- **De-minimis controller-fix carve-out.** When a task-review finding leaves no judgment — a typo, a constant the plan states verbatim, a one-line revert — the controller may apply it in its own session rather than pay a full implementer dispatch. The exception is fenced on every side: it is disclosed in the ledger, it consumes a fix round like any other and is counted everywhere that price is quoted, the covering command runs *before* the commit, the fix is committed before its scoped re-review, and two consecutive uses escape back to a dispatched implementer. A failing covering command means the fix was never de minimis: revert, spend no round, and go back to the round's own rule — which at rounds 4-5 is a fresh takeover implementer on a more capable model, not the original one that rule had already replaced.
- **Two suites could report PASS without observing anything.** Both had an assertion whose passing condition was also satisfied by the work never happening. The SDD integration test's ledger check grepped the bare string `progress.md` across the whole session file — the loaded skill text, assistant prose, and error output all mention it, so a run that made no durable write still matched; it now requires a tool-input key (`file_path` or `command`) targeting the ledger, which cannot appear in prose. The packaging canary ran its build under `|| true` in a file with no `set -e`: a failed build left no archive, `unzip -l` failed, `grep -q` matched nothing, and the else branch reported "canary absent" — proving only that nothing had been built.
- **The SDD integration test completes and reports real statuses.** A full live run (two tasks, task reviews, Codex gates, final review) takes ~23 minutes of agent time, so the 1800s ceiling was killing healthy runs before their analysis phase; the ceiling is now 3600s, overridable via `SDD_INTEGRATION_TIMEOUT`, and a ceiling kill is reported as a timeout instead of being indistinguishable from a crash. Three more defects went with it: `$?` after the `| tee` pipeline reported tee's status, `grep -c … || echo "0"` yielded a two-line `0\n0` on a genuine zero count, and Test 3 asserted a Claude Code task-tracking tool that sits behind ToolSearch in headless runs — where SDD's own plan-scoped ledger is the load-bearing signal. The test now accepts either.
- **Approach-gate degrades are exempt from the ungated-ledger append.** `gate-preflight.md` told every degraded gate to append an event and, on append failure, to say so in the §6 hand-back. The approach gate's route is that one file: `ungated-ledger` rejects any `--gate` token outside `spec|plan|task|final|adhoc`, and §6 lives in `gate-fix-loop.md`, which the approach route excludes — so the shortest route was delivering an instruction it cannot execute and a pointer it cannot resolve. Recorded as a declared post-split edit, preserving the losslessness proof.
- **Deferred minors from the 6.10.0 review train closed.** The losslessness proof exports `LC_ALL=C` for the whole suite — byte-identity is the property under test, and `uniq` and the numeric tiling both collate by locale (under `kk_KZ.PT154` the suite failed six checks before the fix). Both backslash guards read their replacement field with cut ranges matching the consumer loops, so a backslash hiding after an embedded tab is caught. Intra-table duplicate source lines fail loudly instead of last-row-wins. The assemble fixture's links diverge from alphabetical order, so a sorting assembler fails instead of passing by coincidence, and the assembler hard-errors on a sibling `.md` link outside the namespace its discovery pattern can parse instead of silently dropping that content. `example-workflow.md` and `common-rationalizations.md` gained existence and content assertions — either could previously be deleted with every suite still green while the SKILL.md stubs pointed at nothing.
- **`docs/hyperpowers/` is tracked in this repo, and `CLAUDE.md` now says so.** The general rule — stated by the skills themselves and repeated in most `CLAUDE.md` files — is that specs and plans stay uncommitted working files. This repo is the exception and nothing said so, so the standing instruction to gitignore them kept getting applied here. Everywhere else a spec is scaffolding and the change is the deliverable; here the skills are the product, so the reasoning behind each one is part of it. Five planning and spec documents that had been sitting untracked are now committed.
- **Eval harness back to green** (in the separate [hyperpowers-evals](https://github.com/scott-arne/hyperpowers-evals/) clone, not this repo): the opencode provisioning tests are hermetic — they resolved `opencode` through a real `Bun.which` against the host PATH, so nine of fifteen failed on any machine without the CLI installed — the scenario unpin fence records the thirteen fork-added Claude-family pins it had been red on, and a PATH-fallback test that set `process.env.PATH = undefined` (which coerces to the *string* `"undefined"`) now deletes the key so the fallback it asserts can actually fire.
- **Release gating.** Offline: 33/33 suites pass, `test-sdd-contract.sh` at 95 assertions, `test-gate-contract.sh` at 119, `test-gate-split-lossless.sh` at 26 PASS / 0 SKIP, topology 47, placement 28, assemble 8, shell lint clean. Evals harness: `bun test` 1158 pass with one load-dependent 5000ms timeout that passes in isolation, plus `bun run lint`, `bun run typecheck`, and `bun run quorum check` clean. Live: the SDD integration test was verified end-to-end at the 3600s ceiling when its fix landed (STATUS: PASSED, every assertion green); it was not re-run for this release.

## 6.9.2 (2026-08-20)

- **Visual companion is no longer scoped to the architectural path.** The three-path router split (6.9.0) moved the companion's just-in-time step under the `**Architectural:**` checklist header — the line itself was never edited, but the new header landed above it — leaving spike and bounded brainstorms with no mention of the companion at all. Bounded is the modal classification for work in an existing repo, so in practice the companion stopped being offered. It now has a path-independent trigger paragraph (mirroring the Codex approach gate's, added in the same commit that caused the regression), a step on the bounded checklist, and a Red Flags row for "It's bounded, so the visual companion doesn't apply". The `## Visual Companion` section moved above `## After the Design (architectural path)` so it no longer reads as architectural-only. Ceremony still does not escalate: a bounded task that opens the companion stays bounded and still ends in a short in-chat design.
- **New eval scenario** `brainstorming-bounded-fires-visual-companion` guards the bounded path (companion opened just-in-time, no spec file, no plan document).
- **Evidence is inconclusive and recorded as such** (`evals/docs/experiments/2026-08-20-visual-companion-path-scoping.md`). The failure mode reproduced once pre-fix — an agent classified BOUNDED and then stated it would "stay in the terminal rather than opening the visual companion" — but post-fix 3/3 vs pre-fix 2/3 is not statistically distinguishable at that sample size. The change is kept on structural grounds, with no observed cost: across all six runs the bounded classification held, no spec file appeared, and writing-plans never fired.

## 6.9.0 (2026-08-19) — upstream sync batch 3

- **Brainstorming rebuilt as a three-path router.** Every request is classified out loud — spike, bounded, or architectural — and the ceremony scales with the class while the approval gate never does: feasibility spikes get a 2-3 sentence probe plan, bounded changes get a short in-chat design (no spec file), and architectural work runs the full questions → approaches → sectioned design → written spec pipeline. The ratchet is one-way: hidden complexity upgrades the path mid-task; nothing downgrades.
- **Classification keys on outcome shape.** A request naming structure the repo does not have — a new module or layer, a new subsystem, reuse across components that do not exist yet — is architectural even when the first edit looks small; algorithm choices inside an existing function stay bounded. (Eval-driven fix: the initial router text let agents classify by whether the entry-point code exists.)
- **Any-path Codex approach gate.** Real architectural/algorithmic/data-model alternatives — or an explicit request for Codex input — fire the approach gate on any path; on the bounded path its approaches fold into the in-chat design without escalating ceremony.
- **Visual companion**: corrected Copilot CLI backgrounding guidance.
- Release-gated by live evals: adversarial-brief escalation 5/5 (threshold ≥4/5), no-downgrade 5/5, and a bounded-path guard proving the approach gate fires without a spec file being created.

## 6.8.0 (2026-08-19) — upstream sync batch 2

- **Plan-scoped SDD workspaces.** Each plan's scratch (ledger, briefs, reports, review packages) lives in its own cache directory (`~/.cache/hyperpowers/sdd/<repo-key>/plans/<plan-slug>-<hash8>/`), so concurrent plans cannot read or corrupt each other's state; idle sibling workspaces are garbage-collected after 14 days; finish deletes the plan's workspace with real verification (`test ! -d`).
- **SDD lifecycle restructure** (Setup → Task Loop → Final Review → Finish) with a **unified fix loop**: Codex-gate findings and Claude-reviewer findings share one five-round cap per task, one gate directory per task lifecycle (persisted in the ledger across compaction), gate ceilings computed in the shared-cap coordinate system, and a breaker that surfaces BLOCKED to the human rather than parking findings.
- **File-based handoffs threaded through**: `task-brief` and `review-package` carry the plan identity; the review package signature is `PLAN_FILE BASE HEAD [OUTFILE]`.
- **writing-plans** carries a Spec header linking each plan to its source spec.
- Release-gated by live evals: fix-loop convergence and plan-scoped workspace isolation (the latter caught and drove the delete-at-finish hardening).
