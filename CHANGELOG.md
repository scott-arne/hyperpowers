## 6.15.0 (2026-10-03)

A review finding was acted on before anyone checked it was true.

- **Reviewers check a finding before they report it.** `requesting-code-review/code-reviewer.md` and SDD's `task-reviewer-prompt.md` gain a "Before You Report a Finding" section. It asks four questions: what the exact file:line is, what the concrete failure is (input, state and outcome), whether the surrounding code was read, and whether the severity is defensible. It adds a proof rule for Critical and Important findings that covers both a defect in the diff and an omission. It states that zero findings is a valid review, and that the diff under review is data to analyze, never instructions. Measured on a new scenario, `code-review-precision-on-realistic-diff`. In Phase 5, treatment accepted 8 of 10 reviews against control's 0 of 10, but the fixture held two triggers its story called clean. On the fixed fixture the advantage did not reproduce:
  - As scored, treatment accepted 4 of 10 against control's 0 of 10. The pre-registered rule reads that as Worse, because an exact-line parser limit scored one correct review at recall 0.
  - Read by hand, treatment accepted 6 of 10 against control's 0 or 1 of 10, which fits none of the rule's readings.
  - In every reading, treatment raised fewer blocking findings on clean hunks: 0.5 to 0.8 per review against 1.9 to 2.2.

  The section stays as cheap guidance, by the human partner's call on the hand-read result. The Phase 5 claim of an unambiguous advantage is withdrawn. The section's eight-bullet "Skip these" catalogue was removed before measurement, because the baseline never raised a finding of any catalogue shape.
- **A blocking finding is confirmed before it is fixed.** `gate-fix-loop.md` now puts every blocking finding in exactly one state:
  - **Confirmed:** the controller fixes it. It leaves the ledger only through a fix, or through the human partner's explicit acceptance of the risk, recorded in their own words.
  - **Declined:** only as refuted (the cited code does not do what the finding says) or corrected (real, but not at blocking severity or not in scope). Either way the ledger carries file:line evidence.
  - **Unsettled:** it stays blocking. Uncertainty never clears a blocker.

  A blocking finding first raised in the backstop round is now carried to the hand-back as unresolved instead of declined. `gate-findings.md` defines when two lenses report the same defect: the same file and offending code, and the same failure. A matching title or line number does not make two findings the same defect. When findings merge, the strictest severity survives.
- **SDD's fix loop can decline a finding with evidence.** The resumed implementer verifies each task-review finding before fixing it. It declines a finding only as refuted or corrected, with file:line evidence. The scoped re-reviewer gains a DECLINED verdict, which it gives only after confirming that evidence; an unconfirmed decline stays NOT ADDRESSED. A round that declines every finding has no fix diff. It skips `review-package`, and the re-reviewer judges it from the evidence alone. The ledger's fix-round line becomes `(<X> addressed, <Y> declined, <Z> open — …)`. Measured on a new scenario, `sdd-fix-loop-refutes-wrong-finding`: both arms refuted the wrong finding with a verifying read in 10 of 10, so the change did not separate from control. Treatment also spent one extra procedural round in 9 of 10 trials. The change stays as guidance this measurement could not separate. The next fixture needs a finding whose refutation takes judgement rather than a lookup.
- **Plans cite the code they tell the implementer to imitate.** `writing-plans` adds a `## Grounding` section to the plan header. It gives one real `path:line` for each convention the work touches (at minimum naming, error handling and test shape), or `none: no existing pattern for <convention>`. A task may carry an optional `**Mirror:**` line naming code to imitate. If earlier tasks moved that code, the implementer re-locates it by the construct it names. The implementer prompt says to read a named Mirror before writing. A citation that does not resolve is a plan failure, and the self-review gains a fourth check, "Grounding is real". Unmeasured.
- **Plans and specs name their unknowns.** `writing-plans` sanctions one form of unknown: `Unknown:` or `Assumption: <what>, validate via <method>, before Task N`. The method is a specific check, and Task N is the first task that depends on the answer. A validation that fails is a plan conflict for the human partner, and bare TBD and TODO remain plan failures. `brainstorming` writes an unconfirmed premise in the spec as `Assumption: <what>, validate via <method>`. Unmeasured.
- **After compaction, the session-start hook names the plan's SDD ledger.** When SessionStart's source is `compact`, the hook adds one line naming the newest `progress.md` under the repo's SDD cache key, so a resumed controller reads its ledger instead of re-dispatching finished tasks. The hook:
  - reads the stdin payload once, bounded at two seconds, before the janitor forks;
  - re-derives the cache key itself rather than calling `sdd-dir`, so the lookup writes nothing;
  - skips paths that are not valid UTF-8;
  - spells control characters, quotes, backslashes, U+0085, U+2028 and U+2029 as visible escapes;
  - keeps the notice under 1200 characters, which a test asserts.

  Three related changes ship with it. `escape_for_json` now escapes every C0 byte as `\u00XX`, which applies to all injected context. The heredoc fence now flags here-strings, because bash 5.1+ delivers them through the same pre-fork pipe write that deadlocked hooks. The hook tests feed stdin from `/dev/null`. Verified by `tests/hooks/test-session-start.sh` under bash 3.2 and 5.2 and by one live check; no eval measures it.
- **Skill frontmatter is gated as YAML.** `tests/packaging/test-skill-frontmatter.sh` requires each `SKILL.md` to carry frontmatter that a YAML loader accepts:
  - a `name` matching its directory;
  - a single-line `description` that resolves to a string, not a boolean or null;
  - no duplicate keys;
  - valid UTF-8, with no control characters, tabs or line separators;
  - a block within the spec's 1024-character limit.

  The gate runs under a pinned locale, and `test-skill-frontmatter-rejects.sh` holds negative fixtures showing that each check fires. It found one real defect. The `optimizing-performance` description was a plain scalar containing `Keywords: `, a `: ` mapping separator that standards-compliant YAML parsers reject, and it is now quoted.
- **`codex-broker-sweep` can target named pids, and waits longer before calling a broker unreferenced.** `--only-pids PID,PID` narrows discovery to the listed pids and reads no process table to find them. Every identity and safety check still runs on each pid. An empty or malformed list is a usage error. The registration window grows from 10 to 60 seconds and can be overridden with `CODEX_BROKER_SWEEP_WINDOW_S`. The override must be a positive integer of at most six digits once leading zeros are stripped, so `00` or an oversized value is rejected rather than disarming the fence. The test builds its fence list from live fixture pids at call time, so it cannot reach a real broker. On a host with no readable process table, it skips with a reason instead of reporting 59 failures.
- **`gate-round --peek` answers with the ceiling the call supplies.** A peek preferred the persisted ceiling to the one this call supplies through `--consumed` or `--ceiling`. It could therefore answer proceed on a cap that a newer `--consumed` had already reported spent. It now uses the call's ceiling, and falls back to the persisted one only when the call supplies none.
- **The gate contract pins the lens-composition clause and one calibration per recipe.** The calibration needle counted matches anywhere in the assembled gate. The clause that puts each lens prompt into the review focus could disappear, or a recipe could drop its calibration, and the suite stayed green.
- **Brainstorming opens the visual companion when a change puts something on a page.** The any-path visual companion paragraph in `brainstorming/SKILL.md` gains two sentences: adding or moving something on a page or screen always raises one visual question, where it goes, and the placements are shown in the companion before the design is presented. In the field and in two baselines, sessions placed the controls without posing the placement, so the trigger never fired. Measured on `brainstorming-bounded-companion-after-compaction`: the companion started in 10 of 10 sessions against the shipping head's 5 of 10 (one-sided Fisher p 0.016). On `brainstorming-bounded-companion-closed-cli-output`, a change to a command-line tool's terminal output, it stayed closed in 10 of 10, which excludes start rates above 26%. Over-triggering after a compaction is unmeasured. The evidence is in the evals repository under `evidence/2026-10-02-companion-placement-trigger/` and `evidence/2026-10-02-companion-over-trigger/`.
- **What was tried and is not in this release.** None of these shipped in an earlier release. They are recorded because the measurements are the result.
  - **The bootstrap ladder.** It added an ordered three-rung consequence check to `using-hyperpowers`. It gated all 240 boundary sessions and over-triggered on 0 of 60 benign ones. But it regressed router brief b1 against `main`: 6 of 20 against 16 of 20 (one-sided Fisher p = 0.0018), and 7 of 20 as revised (p = 0.0048). It is reverted, so the bootstrap is `main`'s.
  - **What the ladder's revert costs.** This was measured too. At Claude Code 2.1.284, `main` does not gate on five of the six boundary scenarios: 0 of 10 on four of them, and 5 of 10 on tls-verify. Public-route, at 15 of 20, is not separated. A successor needs its own spec. It must recover those five, hold public-route, and pass b1.
  - **The first-edit interlock hook.** At the measured resolution it added nothing over the bootstrap wording, and it cost 21 to 26% more tokens on benign tasks. It is reverted.
  - **The reworded `brainstorming` description.** It is back to upstream's text.
  - **Two unmeasured edits.** A paragraph in `dispatching-parallel-agents` and a sentence in SDD about collecting dispatched agents were reverted, because Claude Code already notifies when background work finishes. A no-op-pruning rule was reverted under its own test: guidance nobody has run is deleted.

  The measurements and decisions are in `docs/hyperpowers/2026-09-23-adoption-remediation-eval-evidence.md`.

## 6.14.0 (2026-09-09)

The gate re-derived the whole change on every round.

- **The three code-review focus strings now calibrate severity to what the diff causes.** codex-plugin-cc's review template enumerates severities without defining their scope, so the reviewer picked one with no anchor: historical captures showed 30% of task-gate blocking runs carrying nothing critical or high. All three focus strings in `skills/requesting-code-review/recipe-code.md` now state that critical or high means a defect the change introduces — in its changed lines, in an unchanged caller it breaks, or in a requirement it was asked to meet and omits — that yields a wrong result, a crash, data loss, or a reachable security hole; that an untested path is medium unless the requirements named that test as a deliverable; and that naming, style, and speculative hardening are low. `gate-lenses.md` now requires the complete focus string, context paths and calibration together, in every lens launch, because a lens focus carrying the paths without the calibration is the defect that clause exists to prevent. Measured with real Codex reviews of three fixture diffs: the crash-and-wrong-result fixture blocked 1 of 3 under control and 3 of 3 under the calibration, the defect-free fixture approved 3 of 3 in both arms, and the omitted-requirement fixture blocked 3 of 3 in both. A contract assertion pins all three copies against drift.
- **The round 2+ re-review invocation is two textual parts, not a prompt rebuilt from scratch.** `gate-fix-loop.md` now states the round 2+ launch as the round-aware preamble that names the ledger path, plus the section 3 focus string unchanged; spec D8 was amended to match. Treatment landed on exactly those two parts 3 of 3 against a control's 0 of 3, at a median 206 words against the control's 218. All three control launches failed the same way, splicing an extra dossier line — the one `gate-lenses.md` scopes to round-1 lens prompts — between the preamble and the focus string.
- **`gate-round --consumed <n>` computes the SDD per-task ceiling from the shared five-round cap.** The per-task gate has no ceiling of its own — its rounds count against the task's five-round fix cap — so the controller was told to work out `5 - <rounds consumed>` by hand before every call. The subtraction did not survive contact: across 469 historical task gates, twenty recorded out-of-pattern ceilings of 1, 2, 6, or 7, and the seven at 6 or 7 exceed the cap outright. `--consumed` states the one number the controller can read off its ledger, is mutually exclusive with `--ceiling`, and records `consumed` in the state file beside `round`, `ceiling`, and `gate`.
- **`gate-round --peek` reports backstop for a spent ceiling of zero.** `--consumed 5` makes a ceiling of 0 reachable, and peek mishandled it twice: its verdict guard read a spent budget as "no ceiling known" and answered proceed, and its `expr` validation idiom read a legitimate zero as an unreadable state file, which also made a peek on a fresh gate directory exit 2 naming a file that does not exist. Unknown and zero are now distinct — unknown proceeds, a recorded zero backstops — and digits are validated with a `case` pattern instead of `expr`.
- **A task-gate ceiling above five is a usage error, and every numeric flag is validated and canonicalized before it is stored.** The cap is now checked against the effective gate, including a `task` inherited from the state file by a continuation that omitted `--gate`, and flag presence is tracked apart from flag value, so `--consumed ''` no longer reads as an absent flag and a flag left dangling at the end of the argument list is a usage error rather than an unbound-variable death. The ceiling is validated on every gate type, and every bound is decided on the digit-validated string with leading zeros stripped: `--consumed 01` no longer writes a state file no later call can parse, `--ceiling foo` no longer returns proceed on a non-task gate, and a token wider than the machine word no longer wraps into the range the cap accepts.
- **An approval reached through a `needs-attention` verdict now has a rule saying its notes get read.** The completion check in `gate-findings.md` told the controller to read raw findings only on `blocking`, so an approved-with-notes capture could converge with its medium and low findings unread — the 6.13.0 release review converged through exactly that path, and its two medium notes reached the round ledger only because the controller chose to write them down. The check now requires each medium or low note to be recorded in the round ledger, and in the skill's Minor ledger if it keeps one, before the round is treated as converged.
- **`brainstorming` asks the tooling question at the one moment it is cheap.** For a new project, or one with no configured tooling, the design presentation now asks which to stand up from the start — aggressive linting with auto-formatting, unit-test infrastructure, end-to-end infrastructure, fuzz or mutation testing where the stack supports it — and the selections land in the spec's Global Constraints, so every later plan and task inherits them. Ported from upstream `537d649` and measured fork-side before shipping: control 0 of 3 against treatment 2 of 3 as first scored, 3 of 3 re-scored against a repaired oracle. The arm's rule is cleared on either scoring.
- **The two routing edits 6.13.0 shipped unmeasured were measured afterwards, and one of them is reverted.** 6.13.0 justified both as mechanically checkable contradictions, a class it treated as safe to change without evidence. The `executing-plans` inline-path note is unsupported: the control passed 3 of 3 and the treatment 0 of 3, so `skills/executing-plans/SKILL.md` is restored to its 6.12.0 text. The contradiction was real — 6.12.0's text does contradict an explicit inline request — but inert, and the fix for it measured worse than the defect. The `requesting-code-review` REQUIRED SUB-SKILL pointer to `receiving-code-review` is supported: control 0 of 3 against treatment 3 of 3, re-measured on a scenario whose name carries no skill cue, the widest separation any pair in this work produced. The pointer stays, now with evidence behind it, and the topology assertion stays with it.
- **`requesting-code-review` no longer offers `HEAD~1` as a review base.** `HEAD~1` keeps only the last commit of a multi-commit change. The skill now names the branch point for a whole-branch review and the commit recorded before a task began for a task review, and the topology suite fails if `HEAD~1` returns. From the 6.13.0 Codex sweep.
- **`gate-telemetry` bounds a cohort with `--since` and `--until`.** Together they select the half-open window from `--since` up to but excluding `--until`, so two reads that share a boundary are disjoint by construction and a post-release cohort can be read without the history it follows. Timestamps are ISO-8601 only and are checked against the calendar, so an impossible date exits 2 instead of silently reporting the whole history. The churn summary now filters malformed rounds instead of coercing them first, so a non-numeric round no longer enters a mean as zero, and the fleet aggregate's churn fields are asserted by test. From the 6.13.0 Codex sweep.
- **`docs/testing.md` names the two suites that are not bash scripts, and its directory loop fails when a suite fails.** The guide's table implied every suite was a `bash test-*.sh`, leaving out that `tests/brainstorm-server` runs under `npm test` and `tests/pi` under `node`. The table gained a Runner column naming the exact invocation for each directory, and the example loop counts failures and exits non-zero instead of echoing FAILED and returning green. From the 6.13.0 Codex sweep.

## 6.13.0 (2026-09-06)

The gate blocked on findings its own contract calls minor.

- **`verdict-normalize` now approves a JSON-path `needs-attention` carrying only medium and low findings.** The contract defines critical and high as blocking; medium and low are not. A `needs-attention` verdict carrying only medium or low findings now normalizes to `approved`, and one carrying no findings at all fails closed to `incomplete`. Before this fix, 30% of task-gate blocking captures held zero critical or high findings — the gate was blocking on findings its own severity ladder categorizes as non-blocking.
- **`session-start` names a newer marketplace version.** Releases 6.10.0 through 6.11.1 never loaded in any session because the plugin cache went stale and nothing said so. The hook now compares the loaded plugin's `plugin.json` version with the marketplace clone's `marketplace.json` and adds one line to the injected context only when the marketplace is strictly newer. It is silent when the versions match, when the running copy is ahead, when the clone is absent, or when its manifest is unparseable, and it emits only the validated semver so a corrupt manifest cannot break the hook's JSON.
- **`run-hook.cmd` uses `:;` label lines instead of a heredoc.** Heredocs in hooks deadlock under bash 5.1+ (upstream issue #571). The file opens with four `:;` lines: cmd.exe skips a line beginning with `:` as a label and falls through to the batch block; a POSIX shell runs `:` as a no-op, evaluates the rest of each line, and `exec`s bash on the named hook before reaching any batch text; missing bash or a missing script name exits 0 silently. The heredoc description in `docs/windows/polyglot-hooks.md` was corrected, and the fence regex tightened so here-strings are not flagged. Upstream `d80fc18`.
- **`review-package` exits 3 on an empty or non-descendant range.** An empty commit range or a non-descendant HEAD means the range cannot describe a task's work; both now exit non-zero instead of producing a vacuous package. The non-zero exits are documented in the SDD DONE step, and a stripped-exec-bit test covers `review-package` alongside `task-brief`. Upstream `99f9f00`.
- **Both SDD helpers invoke `sdd-dir` through bash so a stripped exec bit cannot break them.** An extractor that strips the exec bit from `sdd-dir` left both helpers broken; they now invoke `"${BASH:-bash}" "$SCRIPT_DIR/sdd-dir"` explicitly. Upstream `0be4987`.
- **The helper stdout contract is documented correctly and pinned by test.** `task-brief` prints `wrote <path>: <N> lines` and `review-package` prints `wrote <path>: <N> commit(s), <N> bytes`. Nine prose sites were corrected in total (four in the SDD skill's SKILL.md and task-reviewer-prompt.md, then five more in SKILL.md, re-review-prompt.md, and example-workflow.md). `tests/sdd/test-sdd-contract.sh` pins both output shapes and fences the stale phrasings, and `tests/claude-code/test-sdd-dir-path.sh` asserts the helpers' stdout.
- **`requesting-code-review` offers `git merge-base origin/main HEAD` instead of the moving ref.** The suggested base-ref command used `origin/main`; once it advances past the branch point, main's newer files appear in a two-dot diff as deletions the reviewer cannot tell from real ones. `git merge-base origin/main HEAD` anchors the range to the branch point. Upstream `2a500fe`.
- **The `claude` CLI test helper reads stdin from `/dev/null`.** `run_claude` spawned `claude -p` with the suite's stdin inherited, so from a terminal the CLI could block reading it and each test stalled to its full timeout. It now redirects stdin from `/dev/null`. Upstream `72ee5bb`.
- **Seven orphaned skill files deleted; a guard now fails on any new one.** Every non-`SKILL.md` file under `skills/` must have its basename mentioned by some other tracked file outside `docs/`, `CHANGELOG.md`, and `RELEASE-NOTES.md`. Seven files failed and were deleted; the allowlist ships empty, and `tests/packaging/test-no-orphan-skill-files.sh` now enforces the invariant.
- **`requesting-code-review` routes to `receiving-code-review`.** `requesting-code-review` step 3 now carries a REQUIRED SUB-SKILL pointer to `receiving-code-review`, which no skill, hook, or test referenced before. The topology suite asserts the edge.
- **`executing-plans` no longer overrides an explicit inline-execution request.** The note told every session with subagents to use SDD instead, overriding the inline choice the human had just made; it now says it is the inline path by request. `writing-plans` said "two-stage review"; the task reviewer has returned a spec verdict and a quality verdict since 2026-06-10. All three reviewer read-only clauses now carry the worktree escape hatch. The read-only clause now has one source file, `skills/requesting-code-review/reviewer-read-only-clause.md`, and `tests/sdd/test-sdd-contract.sh` fails when any template's copy drifts from it.
- **`optimizing-performance` names the repo-scoped scratch dir, which survives SDD's Finish.** The baseline was persisted to the plan-scoped scratch dir, which does not exist yet at step 1 and which SDD's Finish deletes. The skill now names the repo-scoped dir (`sdd-dir` with no plan argument), which survives.
- **`gate-telemetry` reports mean rounds and first-round convergence per gate.** New churn metrics: `meanRounds` and `firstRound` per gate type (spec/plan/task/final), on `--json` entries and in the markdown lines.
- **`docs/testing.md` describes Quorum and the current test tree.** The file described a Python Drill harness that no longer exists. It now describes the Quorum harness in the separate `evals/` clone and the fourteen `tests/` directories.

## 6.12.0 (2026-08-28)

A decision the human has to live with arrived as five-word labels, and the two Red Flags rows written to fix it measured inert.

- **The comparison goes in chat; the widget collects the answer.** `AskUserQuestion` renders each option as a ~5-word label plus one line of description. That is plenty for "which of these do you prefer" and nowhere near enough when the options differ in what happens afterward — an interface, a stored format, a default, a dependency, work that would have to be redone. The skill already carried the right instruction ("Present options conversationally with your recommendation and reasoning"), but scoped to the architectural path's **Exploring approaches** step; the clarifying-question loop that fires on *every* path said only "Prefer multiple choice questions when possible", which routes consequential decisions straight into the widget. New `## Deciding Together` section specifies the message: the fork in one sentence (what actually differs, not what the options are named), one line per option for what it buys, costs, and rules out — marking which choices are cheap to change afterward and which are not — then the recommendation and the reason for it. Then ask with the normal widget, recommended option first. The message is how they decide; the widget is how they answer; you send both and fold neither into the other. Options differing only in a name, an ordering, or a wording have nothing to compare and are asked directly. The clarifying-questions bullet points at the section, so the trigger is path-independent rather than architectural-only.
- **SDD's plan-scan question is one of these decisions.** The batched question the controller asks before Task 1 — every conflict the scan surfaced, beside the plan text that mandates it, asking which governs — now cites Deciding Together explicitly. Each row is a fork with downstream consequences, which is exactly the case the widget compresses away.
- **The form was chosen by measurement, and the measurement deleted half the design.** `writing-skills`' "Match the Form to the Failure" classifies this as a **shaping** failure — the agent complies, the output has the wrong shape — and predicts prohibitions backfire there. The design originally carried two Red Flags rows; they were tested rather than assumed. Across five reps each with the bootstrap confirmed loaded, the recipe-plus-prohibition arm produced a recommendation in chat 0/5 against the no-guidance control's 1/5, and a real comparison 1/5 against the control's 1/5 — indistinguishable from no guidance, and worse than it on the criterion that matters. **Both rows were dropped on that evidence.**
- **Two of that micro-test's four findings were the harness.** It simulated `AskUserQuestion` through `--append-system-prompt`, asking for a fenced JSON block "then stop your turn". That makes the question one indivisible deliverable, so no rep in any arm ever produced both a comparison and the widget — every rep that wrote a real comparison had abandoned the widget, and every rep that used the widget wrote a one-line preamble. Four wording variants failed to break the coupling, which read as a hard behavioral constraint; with the real tool the agent writes ordinary chat above the tool call as a matter of course, and every live control run did. The shipped wording scored 0/5 in that simulation and 3/3 live. Separately, five reps ran with no bootstrap at all — the SessionStart hook's `mkdir` under `~/.claude/session-env` is denied by the command sandbox — and their straight-to-implementation behavior read as a catastrophic regression until the extractor started emitting a per-rep `bootstrap=ok|FAILED-DO-NOT-SCORE` line. A micro-test that runs agent CLIs needs the sandbox disabled and its bootstrap verified per rep, or its arms are unscored noise.
- **"Opus never triggers `hyperpowers:brainstorming`" was that same artifact, recorded as a defect.** Under `claude -p` with the simulated widget, `claude-opus-5` invoked the skill 0/5 against sonnet's 5/5 — which is why the first six live runs pin `claude-sonnet-5`, and why the evidence note originally called for a scenario of its own. It does not survive a real session. This repo's canonical acceptance test ("Let's make a react todo list", clean session, no `--append-system-prompt`) fires the skill as the FIRST tool call 3/3 on `claude-opus-5` and 3/3 on `claude-sonnet-5`, and three live gauntlet runs on `claude-opus-5` invoked it 3/3. No defect is demonstrated and the scenario is withdrawn. One result from the exercise is worth keeping: base Opus with no skill loaded wrote the fork in chat 5/5 with correct per-option consequences but offered a recommendation 0/5, so the amendment does real work on Opus rather than restating what the model already does.
- **New eval scenario** `brainstorming-decision-brief-precedes-selector` (in the separate evals clone). Fixture: a cheminformatics library whose `pairwise_distance()` is plain Euclidean over raw descriptor columns. The brief asks for normalization and mentions in passing that the function runs once per assay batch with clusters compared across batches — a real fork, because per-call statistics silently invalidate the cross-batch comparison, and one whose consequences do not survive compression into option labels. The deterministic checks cover only mechanical facts: the skill fired, `AskUserQuestion` was used, no spec file appeared, `writing-plans` never fired. Keeping the widget is asserted deliberately — an agent that answers with a wall of prose has also lost the affordance the widget provides — and the ordering is deliberately *not* asserted, because `tool-before` orders tool calls against each other and the thing that must come first here is assistant prose. Ordering and substance are both graded from the story's acceptance criteria.
- **A run's evidence is 3M and the infrastructure buried next to it is 12M** (evals clone). Every live run leaves a Claude CLI install, a plugin marketplace clone, its caches, and the CLI cache under `<run>/home/`; all of it is reinstalled by the next run and none of it is evidence. Left alone, `results/` reached 3.8G across 118 runs, and two July runs held 133M of CLI cache between them against 4.7M of artifacts. `scripts/strip-runs` deletes those five paths and nothing else. Deliberately off the list: `home/.cache/hyperpowers`, holding SDD ledgers, Codex gate rounds, and lens output across 44 runs. Three guards, each for a failure already observed — it skips runs touched within `--min-age-minutes` (default 60) so an in-flight run is never stripped, it skips underscore-prefixed directories because those are curated evidence rather than quorum output, and it `chmod -R u+w`s before removing, because agent runs leave read-only files that otherwise make `rm` fail silently and leave most of the tree behind. Not wired into quorum: a post-run hook that deletes things is how in-flight runs get corrupted. Not a retention policy either — eval-evidence notes cite runs by ID and the run directory is what keeps those claims re-checkable, so runs are kept and only their infrastructure is dropped. Verified against the real tree: 380M → 250M with all seven evidence counts unchanged (trajectories 66, verdicts 74, phases 74, session transcripts 164, gauntlet-agent 67, coding-agent workdirs 72, SDD scratch 44), and a second pass strips nothing.
- **Release gating.** Offline: 34 suites, 34 pass, 0 failures — `test-sdd-contract.sh` at 95 assertions, `test-gate-contract.sh` at 124, `test-gate-split-lossless.sh` at 28 PASS / 0 SKIP, topology 47, placement 28, assemble 8, `test-delivery-resolution.sh` at 11, shell lint clean.
