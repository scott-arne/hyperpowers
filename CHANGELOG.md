## 6.12.0 (2026-08-28)

A decision the human has to live with arrived as five-word labels, and the two Red Flags rows written to fix it measured inert.

- **The comparison goes in chat; the widget collects the answer.** `AskUserQuestion` renders each option as a ~5-word label plus one line of description. That is plenty for "which of these do you prefer" and nowhere near enough when the options differ in what happens afterward — an interface, a stored format, a default, a dependency, work that would have to be redone. The skill already carried the right instruction ("Present options conversationally with your recommendation and reasoning"), but scoped to the architectural path's **Exploring approaches** step; the clarifying-question loop that fires on *every* path said only "Prefer multiple choice questions when possible", which routes consequential decisions straight into the widget. New `## Deciding Together` section specifies the message: the fork in one sentence (what actually differs, not what the options are named), one line per option for what it buys, costs, and rules out — marking which choices are cheap to change afterward and which are not — then the recommendation and the reason for it. Then ask with the normal widget, recommended option first. The message is how they decide; the widget is how they answer; you send both and fold neither into the other. Options differing only in a name, an ordering, or a wording have nothing to compare and are asked directly. The clarifying-questions bullet points at the section, so the trigger is path-independent rather than architectural-only.
- **SDD's plan-scan question is one of these decisions.** The batched question the controller asks before Task 1 — every conflict the scan surfaced, beside the plan text that mandates it, asking which governs — now cites Deciding Together explicitly. Each row is a fork with downstream consequences, which is exactly the case the widget compresses away.
- **The form was chosen by measurement, and the measurement deleted half the design.** `writing-skills`' "Match the Form to the Failure" classifies this as a **shaping** failure — the agent complies, the output has the wrong shape — and predicts prohibitions backfire there. The design originally carried two Red Flags rows; they were tested rather than assumed. Across five reps each with the bootstrap confirmed loaded, the recipe-plus-prohibition arm produced a recommendation in chat 0/5 against the no-guidance control's 1/5, and a real comparison 1/5 against the control's 1/5 — indistinguishable from no guidance, and worse than it on the criterion that matters. **Both rows were dropped on that evidence.**
- **Two of that micro-test's four findings were the harness.** It simulated `AskUserQuestion` through `--append-system-prompt`, asking for a fenced JSON block "then stop your turn". That makes the question one indivisible deliverable, so no rep in any arm ever produced both a comparison and the widget — every rep that wrote a real comparison had abandoned the widget, and every rep that used the widget wrote a one-line preamble. Four wording variants failed to break the coupling, which read as a hard behavioral constraint; with the real tool the agent writes ordinary chat above the tool call as a matter of course, and every live control run did. The shipped wording scored 0/5 in that simulation and 3/3 live. Separately, five reps ran with no bootstrap at all — the SessionStart hook's `mkdir` under `~/.claude/session-env` is denied by the command sandbox — and their straight-to-implementation behavior read as a catastrophic regression until the extractor started emitting a per-rep `bootstrap=ok|FAILED-DO-NOT-SCORE` line. A micro-test that runs agent CLIs needs the sandbox disabled and its bootstrap verified per rep, or its arms are unscored noise.
- **"Opus never triggers `hyperpowers:brainstorming`" was that same artifact, recorded as a defect.** Under `claude -p` with the simulated widget, `claude-opus-5` invoked the skill 0/5 against sonnet's 5/5 — which is why the first six live runs pin `claude-sonnet-5`, and why the evidence note originally called for a scenario of its own. It does not survive a real session. This repo's canonical acceptance test ("Let's make a react todo list", clean session, no `--append-system-prompt`) fires the skill as the FIRST tool call 3/3 on `claude-opus-5` and 3/3 on `claude-sonnet-5`, and three live gauntlet runs on `claude-opus-5` invoked it 3/3. No defect is demonstrated and the scenario is withdrawn. One result from the exercise is worth keeping: base Opus with no skill loaded wrote the fork in chat 5/5 with correct per-option consequences but offered a recommendation 0/5, so the amendment does real work on Opus rather than restating what the model already does.
- **New eval scenario** `brainstorming-decision-brief-precedes-selector` (in the separate evals clone). Fixture: a cheminformatics library whose `pairwise_distance()` is plain Euclidean over raw descriptor columns. The brief asks for normalization and mentions in passing that the function runs once per assay batch with clusters compared across batches — a real fork, because per-call statistics silently invalidate the cross-batch comparison, and one whose consequences do not survive compression into option labels. The deterministic checks cover only mechanical facts: the skill fired, `AskUserQuestion` was used, no spec file appeared, `writing-plans` never fired. Keeping the widget is asserted deliberately — an agent that answers with a wall of prose has also lost the affordance the widget provides — and the ordering is deliberately *not* asserted, because `tool-before` orders tool calls against each other and the thing that must come first here is assistant prose. Ordering and substance are both graded from the story's acceptance criteria.
- **A run's evidence is 3M and the infrastructure buried next to it is 12M** (evals clone). Every live run leaves a Claude CLI install, a plugin marketplace clone, its caches, and the CLI cache under `<run>/home/`; all of it is reinstalled by the next run and none of it is evidence. Left alone, `results/` reached 3.8G across 118 runs, and two July runs held 133M of CLI cache between them against 4.7M of artifacts. `scripts/strip-runs` deletes those five paths and nothing else. Deliberately off the list: `home/.cache/hyperpowers`, holding SDD ledgers, Codex gate rounds, and lens output across 44 runs. Three guards, each for a failure already observed — it skips runs touched within `--min-age-minutes` (default 60) so an in-flight run is never stripped, it skips underscore-prefixed directories because those are curated evidence rather than quorum output, and it `chmod -R u+w`s before removing, because agent runs leave read-only files that otherwise make `rm` fail silently and leave most of the tree behind. Not wired into quorum: a post-run hook that deletes things is how in-flight runs get corrupted. Not a retention policy either — eval-evidence notes cite runs by ID and the run directory is what keeps those claims re-checkable, so runs are kept and only their infrastructure is dropped. Verified against the real tree: 380M → 250M with all seven evidence counts unchanged (trajectories 66, verdicts 74, phases 74, session transcripts 164, gauntlet-agent 67, coding-agent workdirs 72, SDD scratch 44), and a second pass strips nothing.
- **Release gating.** Offline: 34 suites, 34 pass, 0 failures — `test-sdd-contract.sh` at 95 assertions, `test-gate-contract.sh` at 124, `test-gate-split-lossless.sh` at 28 PASS / 0 SKIP, topology 47, placement 28, assemble 8, `test-delivery-resolution.sh` at 11, shell lint clean. Every count is unchanged from 6.11.1, and that is the honest reading: **this release adds no offline assertion**, because the behavior it changes — what an agent writes in chat before a tool call — is not observable offline. Its guard is the live scenario. Evals harness: `bun test` 1159 pass / 0 fail across 114 files — no timeouts this time, where 6.11.1 recorded four — plus `bun run lint`, `bun run typecheck`, and `bun run quorum check` clean, the new scenario validating among them. Live: the gauntlet on `brainstorming-decision-brief-precedes-selector` at nine runs — control 0/3 pass, treatment `claude-sonnet-5` 3/3, treatment `claude-opus-5` 3/3 with 4/4 deterministic post-checks in each — plus six canonical trigger-acceptance sessions, 3/3 on each model. **The live skill suites were not re-run for this release:** `test-subagent-driven-development.sh`, `test-worktree-native-preference.sh`, `explicit-skill-requests`, and the SDD integration test all last ran green at 6.11.1. `subagent-driven-development/SKILL.md` did change here — one sentence added inside the plan-scan paragraph — so that suite's staleness is a real gap rather than a formality.

## 6.11.1 (2026-08-26)

A blocking finding raised in the gate's last permitted round had a silent default, and the ledger append that follows it read as free.

- **The backstop's tail finding now forces a stated choice.** A blocking finding first raised IN the backstop round has no round left to confirm its fix — the round that found it is the last one. §5 already conceded the consequence ("fixes applied in the backstop round ship without a confirming Codex pass") but left *fixing it* as the unstated default, so the decline option §5 grants two steps earlier was invisible exactly where it matters most. The stop-condition now names three dispositions with each one's price: **decline** with recorded reasoning (ships no unverified change and buys no follow-on gate — usually right when the fix is not trivial), **fix and open the follow-on review now** while the context is live, or **fix and defer**, only after telling your human partner plainly that a blocking-severity fix rides unreviewed until that review happens.
- **The `backstop-fix` ledger append is priced, not bookkeeping.** A pending event does not discharge a gate — `gate-sweep` gives each one a fresh `GATE_DIR` and runs the full §5 loop at the code-gate ceiling. So both fix paths cost the same extra gate and differ only in when it is paid, and the text now says so. A downstream project hit this twice in one branch and paid two unbudgeted gates for it; the price was recoverable from §7, but nothing on the fix loop's own route pointed at it. The consequence is stated without naming the section: no route contains both `gate-fix-loop` and `gate-sweep`, so a pointer there would be the same dangling reference the approach gate just had removed.
- **"Budget a round for the fix" was the reported remedy and does not work.** For any finite ceiling the last round has no successor, and the round-aware preamble explicitly permits genuinely new blocking findings on re-review — so reserving a round turns a finding budget of 3 into 2 with an identical ungated tail. The gap is a property of terminating, not of the ceiling's size. What the tail needs is a decision procedure, not more budget.
- **New eval scenario** `codex-gate-backstop-finding-forces-choice` (in the separate evals clone): a stub Codex returns a different blocking finding every round, so the loop cannot converge and exits by backstop with a live finding. Deterministic checks pin the skill invocation, the companion call, and one `gate-round` invocation carrying the code-gate `--ceiling 3`; whether the disposition was named — and its price stated — is graded from the story's acceptance criteria. The ungated-ledger append is deliberately not asserted: declining is a legal disposition and writes no entry, so requiring it would fail the best answer.
- **The losslessness proof now watches the post-split edits channel.** Its reference-coverage check enumerates positional words by grepping the *pinned pre-split original*, so that candidate set is frozen by construction — and the edits declared in `gate-post-split-edits.tsv` are a second content channel applied after every reference has been enumerated. Two shapes slipped through. An edit could introduce a positional reference nobody certified, and could not be legalized after the fact, because the coverage check pins the table's key set to the original's candidates. And an edit could rewrite a line that a `verbatim` reference row points AT, voiding the declaration that the reference still resolves. This release's own rewrite is the second shape: line 645 now carries both a referent and an edit. Two guards close it — no edit may introduce or multiply positional references relative to the line it replaces, and the count of edits landing on a referenced line is pinned at 2 (`443->450`, `631->645`) so a third has to be argued for. Both share one regex with the coverage check, so the guard provably polices what that check enumerates, and both were mutation-tested in each direction. The enumeration's comment, which claimed to catch future references, was the misreading that hid the gap; it now says what it is.
- **Two harness defects that made the live suites lie.** Neither is a regression from this release — both predate the branch, and running the live suites is what surfaced them. The SDD integration test verified the base checkout, but SDD's own Setup step mandates a worktree and commits there, so the base keeps nothing but the initial commit. It reported "src/math.js not created" about a file the run had created one directory away. The visible failures were the harmless half: the same mismatch let two checks *pass* over files that were not there, which is worse, because a pass reads as evidence. `npm test` exited 0 because `node --test` exits 0 when it finds no test files at all, and the extra-features check fell through `grep … 2>/dev/null` into an else-branch announcing "No extra features added" about a file that did not exist. The test now resolves the delivery directory by searching the repo's worktrees for the deliverable, requires the runner to report at least one *executed* test before calling it a pass, and reports the extra-features check as SKIP when its subject is missing — absence of the subject is inconclusive, not compliant. Second defect: `run-skill-tests.sh` mapped every exit 124 to its own suite ceiling, but `run_claude` wraps each prompt in a second `timeout` and propagates that 124 upward, so a 90-second prompt cap surfaced as "timeout after 3900s" and sent triage hunting a 65-minute hang that never happened. Elapsed time separates the two now, and the SDD content suite's per-prompt cap is 300s — at 90s the answer expired mid-sentence while every assertion it had reached was green, which makes the suite a latency test rather than a behavior test.
- **New offline suite `test-delivery-resolution.sh`** pins both halves of the first defect — and the third one below — at 11 assertions. It *extracts* the resolution, npm-test, and session-transcript blocks from the integration test rather than copying them, so it cannot drift from the code it certifies, and runs them against synthetic git fixtures: delivery in a worktree, delivery in the base checkout, delivery nowhere, and a decoy worktree that must not shadow the real one; then tests-ran, no-test-files, and tests-failed; then a transcript re-homed to a worktree-named sibling, one sitting in the base directory, a foreign project's transcript that must not be adopted, and nothing anywhere. The resolution and npm-test blocks were mutation-tested in each direction. Writing it immediately paid for itself twice. It caught the first draft of the resolution deciding whether to print its search diagnostic by comparing `$DELIVERY_DIR` against `$TEST_PROJECT` — inferring the outcome from a path rather than recording it. `git worktree list` reports *physical* paths, so wherever `$TEST_PROJECT` is already physical, a successful match against the base checkout produces the identical string and reads as a fallback, announcing a search for a deliverable that had just been found; the two cases are indistinguishable. Under macOS's symlinked tmpdir the forms differ and it happens to behave, which is how it survived. An explicit match flag replaced it. Second, the suite caught one of its own fixtures passing for the wrong reason — a missing `test` script rather than the failing test it claimed to exercise. The alternative to all of this was a ~25-minute live run per iteration.
- **A third harness defect, surfaced by closing the second one's coverage gap.** Verifying the worktree delivery path live first needed a way to make SDD *choose* that shape: `using-git-worktrees` takes a linked worktree only when the instructions declare a worktree directory preference or a project-local `.worktrees/` already exists, and a headless run declares neither — which is why every prior run had branched in place. Supplying both (`SDD_INTEGRATION_WORKTREE=1`) made the shape deterministic; the declared preference also answers the consent question a headless run has no way to ask. That run then delivered into `.worktrees/math-functions`, finished every task, both per-task Codex gates and the final review — and died on `Could not find session transcript file`. Claude Code names its project directory after the session's cwd and re-homes the JSONL when the controller enters the worktree, so the base directory held nothing but an empty `memory/`. It is the delivery defect one layer up: the harness looking where the artifact is not. The lookup now searches the base directory and its worktree-named siblings, newest first, anchored on the run's own tmp path so a concurrent session cannot be adopted. Both shapes occur — the first worktree run re-homed, the second kept its transcript in the base directory while still delivering into a worktree — and both are now covered live and offline.
- **The live suites that call `run_claude` were certifying the installed plugin, not this tree.** `claude -p` without `--plugin-dir` resolves whichever hyperpowers is installed in the ambient plugin home — 6.9.2 on this machine — so a green run attested that the *installed* copy behaves. The integration test had always passed the flag, and so had `explicit-skill-requests`' own runner; `run_claude` had not, which left the two kinds of live suite silently testing different code. It now defaults to the repo root, overridable with `HYPERPOWERS_PLUGIN_DIR`. Every live suite in the gating list below was re-run through it afterward.
- **`test-worktree-native-preference.sh` could not see the behavior it exists to catch.** Its detector reaches `git worktree add` from an anchor word through `\s*` alone, so a colon or a markdown backtick between the two hid the usage entirely — and markdown is exactly how an agent answers "report exactly what command you used". Of six realistic phrasings, two matched; the misses included ``I used `git worktree add ...` `` and a `$ ` shell transcript. The `$` alternative in the anchor group was dead code besides: ERE reads `$` as an end-of-line anchor wherever it sits, never as a prompt character. The scan text is now stripped of backticks, bold markers, and a leading prompt before the tuned anchors run — all seven probes flag, while both of this release's real GREEN and PRESSURE transcripts still pass despite naming `git worktree add` three times in discussion. Separately, `set -e` aborted the `all` branch on a GREEN failure before `green_result` was ever assigned, so PRESSURE never ran and the summary never printed; both phases now report independently. Both fixes were mutation-tested in each direction with a stub `claude`.
- **Release gating.** Offline: every suite passes, with `test-gate-contract.sh` at 124 assertions (five new needles, one per branch of the choice plus the priced append), `test-gate-split-lossless.sh` at 28 PASS / 0 SKIP over 10 declared post-split edits, topology 47, placement 28, assemble 8, `test-sdd-contract.sh` at 95, the new `test-delivery-resolution.sh` at 11, shell lint clean — 34 offline suites, 0 failures. Evals harness: `bun run lint`, `bun run typecheck`, and `bun run quorum check` clean; `bun test` passes apart from four load-dependent 5000ms timeouts on temp-dir fixtures that all pass at a 30s timeout. ## 6.11.0 (2026-08-26)

Subagent-driven development's progress record and evidence discipline, a new controller-fix carve-out, and two test suites that could report PASS without observing anything.

- **The ledger — not conversation memory — is SDD's progress record.** The implementer's agent identity is written into the ledger when the dispatch returns, so a controller resuming after compaction can still resolve fix-loop rounds 1-3 to the agent that did the work instead of dispatching a stranger. Todos mirror the ledger where they are surfaced rather than competing with it, and resume now classifies an in-flight dispatch instead of reading a task with no completion line as never started.
- **A covering command that cannot fail is not evidence.** Every implementer and fix dispatch names either a real covering command or an explicit `no covering command: <rationale>` line plus the controller's substitute verification; a dispatch naming neither is malformed. The controller re-runs the named command itself before acting on any completed-status report — the worked example now shows that re-run before both the review and the re-review.
- **De-minimis controller-fix carve-out.** When a task-review finding leaves no judgment — a typo, a constant the plan states verbatim, a one-line revert — the controller may apply it in its own session rather than pay a full implementer dispatch. The exception is fenced on every side: it is disclosed in the ledger, it consumes a fix round like any other and is counted everywhere that price is quoted, the covering command runs *before* the commit, the fix is committed before its scoped re-review, and two consecutive uses escape back to a dispatched implementer. A failing covering command means the fix was never de minimis: revert, spend no round, and go back to the round's own rule — which at rounds 4-5 is a fresh takeover implementer on a more capable model, not the original one that rule had already replaced.
- **Two suites could report PASS without observing anything.** Both had an assertion whose passing condition was also satisfied by the work never happening. The SDD integration test's ledger check grepped the bare string `progress.md` across the whole session file — the loaded skill text, assistant prose, and error output all mention it, so a run that made no durable write still matched; it now requires a tool-input key (`file_path` or `command`) targeting the ledger, which cannot appear in prose. The packaging canary ran its build under `|| true` in a file with no `set -e`: a failed build left no archive, `unzip -l` failed, `grep -q` matched nothing, and the else branch reported "canary absent" — proving only that nothing had been built.
- **The SDD integration test completes and reports real statuses.** A full live run (two tasks, task reviews, Codex gates, final review) takes ~23 minutes of agent time, so the 1800s ceiling was killing healthy runs before their analysis phase; the ceiling is now 3600s, overridable via `SDD_INTEGRATION_TIMEOUT`, and a ceiling kill is reported as a timeout instead of being indistinguishable from a crash. Three more defects went with it: `$?` after the `| tee` pipeline reported tee's status, `grep -c … || echo "0"` yielded a two-line `0\n0` on a genuine zero count, and Test 3 asserted a Claude Code task-tracking tool that sits behind ToolSearch in headless runs — where SDD's own plan-scoped ledger is the load-bearing signal. The test now accepts either.
- **Approach-gate degrades are exempt from the ungated-ledger append.** `gate-preflight.md` told every degraded gate to append an event and, on append failure, to say so in the §6 hand-back. The approach gate's route is that one file: `ungated-ledger` rejects any `--gate` token outside `spec|plan|task|final|adhoc`, and §6 lives in `gate-fix-loop.md`, which the approach route excludes — so the shortest route was delivering an instruction it cannot execute and a pointer it cannot resolve. Recorded as a declared post-split edit, preserving the losslessness proof.
- **Deferred minors from the 6.10.0 review train closed.** The losslessness proof exports `LC_ALL=C` for the whole suite — byte-identity is the property under test, and `uniq` and the numeric tiling both collate by locale (under `kk_KZ.PT154` the suite failed six checks before the fix). Both backslash guards read their replacement field with cut ranges matching the consumer loops, so a backslash hiding after an embedded tab is caught. Intra-table duplicate source lines fail loudly instead of last-row-wins. The assemble fixture's links diverge from alphabetical order, so a sorting assembler fails instead of passing by coincidence, and the assembler hard-errors on a sibling `.md` link outside the namespace its discovery pattern can parse instead of silently dropping that content. `example-workflow.md` and `common-rationalizations.md` gained existence and content assertions — either could previously be deleted with every suite still green while the SKILL.md stubs pointed at nothing.
- **`docs/hyperpowers/` is tracked in this repo, and `CLAUDE.md` now says so.** The general rule — stated by the skills themselves and repeated in most `CLAUDE.md` files — is that specs and plans stay uncommitted working files. This repo is the exception and nothing said so, so the standing instruction to gitignore them kept getting applied here. Everywhere else a spec is scaffolding and the change is the deliverable; here the skills are the product, so the reasoning behind each one is part of it. Five planning and spec documents that had been sitting untracked are now committed.
- **Eval harness back to green** (in the separate [hyperpowers-evals](https://github.com/scott-arne/hyperpowers-evals/) clone, not this repo): the opencode provisioning tests are hermetic — they resolved `opencode` through a real `Bun.which` against the host PATH, so nine of fifteen failed on any machine without the CLI installed — the scenario unpin fence records the thirteen fork-added Claude-family pins it had been red on, and a PATH-fallback test that set `process.env.PATH = undefined` (which coerces to the *string* `"undefined"`) now deletes the key so the fallback it asserts can actually fire.
- **Release gating.** Offline: 33/33 suites pass, `test-sdd-contract.sh` at 95 assertions, `test-gate-contract.sh` at 119, `test-gate-split-lossless.sh` at 26 PASS / 0 SKIP, topology 47, placement 28, assemble 8, shell lint clean. Evals harness: `bun test` 1158 pass with one load-dependent 5000ms timeout that passes in isolation, plus `bun run lint`, `bun run typecheck`, and `bun run quorum check` clean.
